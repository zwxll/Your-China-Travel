# 自选省份书架分享设计（待用户审阅）

## 目标与范围

用户选择部分或全部已有省份，上传后得到一张海报、一个二维码。访客无需登录，扫码查看所选省份书架，进入城市后继续使用现有多图纸本相册、照片放大与 550 毫秒跟手翻页。上传者也无需登录。

仅公开用户主动选择的照片压缩副本及旅行文字。未选择的省份、视频、账号、本地路径、私有原图地址和管理密钥不公开。原资料保持不变；不是整套本地资料的备份服务。

原省份旁的“分享”保留。新选择分享每次创建独立链接，不覆盖旧单省链接；此次不增加分享历史管理、撤销、有效期或后台自动同步功能。

## 当前结构与选型

当前 `assets/memory-share.js` 把最长边 900px、JPEG 0.7 的照片作为 Base64 写进快照，前端仅接收一个省份。Edge Function、快照校验及数据库均有 12 MiB 上限。只提高一个常量不能解决整包上传、手机加载和数据库膨胀。

选择 Supabase Storage 保存单独照片、数据库保存目录与对象路径。已有 GitHub Pages 继续承载前端。不改用 Sites，不把个人照片提交到 GitHub。

备选是汇总现有单省链接，改动较少但仍无法解决某省超过 12 MiB；更强压缩会降低画质且不能稳定支持大书架，故不选。

## 上传者界面

书架顶部增加“分享书架”。弹窗逐项列出省份、城市数量和已有照片数量，提供全选、取消全选、已选计数、取消及“上传并生成海报”。初始不自动勾选；无照片省份标注并禁选，全选只选择有照片省份。未选任何项不能提交。

提交前明确提示：所选照片及旅行文字会生成公开副本，任何持有二维码或链接的人均可查看。确认之后才读取照片、压缩及上传。

显示正在处理的省份、照片序号和上传进度。发生读取、压缩、网络、容量或发布错误时恢复按钮并保留原因。仅在全部照片上传且目录成功发布后生成二维码；海报生成失败则仍提供已发布链接及重试提示，不宣称上传失败。

多省海报标题为“我的旅行记忆”，保留总省份、城市及照片数量，展示最多六个省份封面并注明其余省份数量；二维码链接包含全部选中省份，不限于海报展示的六个。单省海报继续使用省名。

## 新数据与接口

保留旧版 `version:1` 内嵌照片快照读取及原 `publish` 兼容路径。新版 `version:2` 保存省份、城市文字、照片名称及受控对象路径，不保存长效签名 URL。

扩展现有 `memory-shelf-share` 函数：

1. `begin`：使用随机分享 UUID 和浏览器生成的 256 位管理密钥创建上传会话；只存密钥哈希，登记限定的对象数量及目录。完成容量、格式和发布配额检查后才接收媒体。
2. `upload`：每次发送一张压缩 JPEG（含受控照片编号与管理凭证）。服务端限制实际请求体及图片格式，只能写当前会话对应路径；不得接受任意 bucket、任意对象路径或覆盖他人文件。使用服务端 Storage 客户端写文件，浏览器不获得 service-role 密钥或无限制上传权限。
3. `finish`：核验清单内文件均已上传、总字节数符合额度；校验并原子发布最终目录。未完成会话不允许公开读取。重复完成请求幂等，不额外创建分享。
4. `read`：旧版按原方式返回；新版返回所选省份与城市目录及必要封面访问地址。
5. `read-city`：只读取已发布分享清单中指定的城市，返回该城市照片的短期签名地址；拒绝请求不属于此分享的对象。进入城市时才加载其照片。

沿用现有 `memory_shelf_shares` 存新版目录；增加受保护上传会话与文件登记结构，记录配额、已上传状态和最后活动时间。失败重试同一会话按编号幂等，不重复计费；相同编号不同内容拒绝替换。各份新分享使用独立目录，不删除旧分享。

## 权限、容量与隐私

私有 Storage bucket，不开放匿名直接写入、枚举或删除。通过验证管理凭证的服务端函数执行上传；数据库开启 RLS，继续撤销 anon/authenticated 直接访问分享和会话表。所有外部读请求只返回发布过的内容。

新版目录仍可保留 12 MiB 请求上限，但照片逐文件上传，因此总照片不再受 12 MiB 整包限制。拟定初始保护上限：每份最多 34 省、400 城、1500 张照片，单张压缩 JPEG 最大 300 KiB、照片与封面合计最大 150 MiB；每个来源每天允许的新上传累计最多 300 MiB，并保留发布次数限制。额度须以服务端并发安全的数据库操作扣减，不相信客户端声明大小。分享超过实际空间配额仍需明确失败，不能承诺无限容量。

以上数字是此项目建议值，不是 Supabase 套餐额度；部署前核实实际项目存储和流量预算。匿名访问无法完全防刷；IP 限额只作基本保护，来源 IP 必须取可信平台提供的值。失败会话可用管理凭证取消并清理该会话文件；遗留过期草稿列入部署维护清理步骤，不自动删除已发布书架。

持有二维码等于持有查看权限，短期签名图片链接不是防截图或防转发措施。管理密钥只留在上传浏览器，不能放进二维码；清除浏览器数据可能失去该分享的管理权限。

## 读取与兼容

`memory-share-reader.js` 按快照版本处理：旧链接不迁移也不失效；新版先展示选中省份书架，打开城市才请求对应照片并交给现有相册渲染。切城时丢弃过时请求结果，返回书架销毁阅读器，签名过期后再次进入城市重新获取。

相框、首尾摄影封面、多图分组、手机跟手翻页及电脑双页保持不变。新照片 URL 仅允许来自指定分享存储，通过后端路径校验生成；旧版 Base64 格式校验继续保留，不直接放开任意外部图片地址。

## 变更文件与发布顺序

只触及 `index.html` 的记忆书架分享入口、`assets/memory-share.js`、分享弹窗 CSS、只读阅读器、新后端校验/接口、必要数据库/Storage 配置、分享测试及交接说明。当前工作区中的照片流及个人资料等无关修改不并入本任务。

先实现本地和模拟后端测试；上线时先部署向后兼容的 Supabase 表、bucket 与函数，使用人工构造照片做最小线上验证并删除测试分享，再发布 GitHub Pages。不得为测试自动上传用户的个人旅行照片。代码提交、推送及线上部署在用户授权的执行范围内明确安排，不把设计文档提交等同于已部署功能。

## 验收

- 勾选两省生成一个二维码；第三个未选省份不上传、不显示。
- 全选覆盖所有有照片省份；空选择不能提交，无照片省份有明确提示。
- 超过 12 MiB 的总照片仍能分文件发布并逐城浏览，照片不重复、不缺失。
- 上传中断不会公开残缺书架；重试上传与完成请求幂等；错误可见且按钮恢复。
- 错误管理密钥、跨会话对象、任意外部地址、超额文件、伪造字节数、非法图片及并发超额均拒绝。
- 新旧二维码均可只读浏览；单省既有更新行为不变，新多省分享不覆盖它。
- 手机和电脑的封面、照片放大、多图排版、上一页/下一页及边缘松手翻页回归通过。
- 完整测试套件、数据库权限检查及独立线上模拟数据验证通过后，才宣称功能可用；微信真机另行验收。
