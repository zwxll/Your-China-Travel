# 旅行年轮树：独立轻量场景设计

## 目标与边界

新增“旅行年轮树”功能，在现有功能菜单中单独进入。它使用项目已有的城市照片，用树形和年份年轮表达旅行记忆；场景规模接近伞幕照片，不扩展成新的地图或统计系统。

用户已确认：原伞幕照片必须完整保留，内部文件、视觉和操作均不修改。参考对话只是创意来源，不照搬省份树枝、路径、里程或生长动画等全部设想。

## 视觉设计

- 中央是一棵暖木色艺术记忆树，有清晰树干、自然弯曲的主枝与少量叶簇，不使用油纸伞。
- 城市照片围绕不同枝条分组悬挂；通过前后层次与间距展开，不额外添加演示照片，不把全部照片堆成一个平面。
- 树冠和整体构图接近现有伞幕尺寸；下方为紧凑小花园，暖米色背景、柔和光照，不增加河流或广阔远景。
- 树根附近设置浅木色底座和细淡的年份同心线。年份数量取自真实数据；中心到外圈按年份从早到晚排列，不编造缺失年份。
- 年份文字与筛选按钮保持清晰、克制，不覆盖主要照片。手机端允许年份按钮横向滚动。
- 独立场景标题为“旅行年轮树”，副文案为“把走过的城市，长成自己的记忆”。

## 功能与数据

1. 功能菜单新增“旅行年轮树”按钮，沿用菜单现有按钮样式。电脑和手机均可打开独立全屏场景，返回后恢复按钮焦点。
2. 使用现有 `collectJourneyArchiveData()`、`getPhotosByCity()` 与 `TravelImageAtlas.collect()` 获取城市相册照片；排除视频，不额外加入景点相册、封面或远程素材。
3. 年份规则与年轮照片一致：手动归属优先，其次照片明确旅行日期，否则城市首次到访年份；不以上传日期猜测拍摄年份。读取已有 `imageAtlasYears`，本模块不写数据库、不修改归属。
4. 同一城市多次到访不重复加入同一张照片；城市间各自保存的记录按现有记录标识保留。
5. 默认显示全部照片。点击年份按钮，突出该年照片并淡化其他年份；其他照片仍保留布局。选择“全部”恢复，不反复创建树和照片对象。
6. 年轮地面图形同步所选年份的强调色，年份按钮是明确可点击入口；首版不要求直接点击三维地面年轮。
7. 保留拖动旋转、滚轮缩放、按城市浏览、点击看原图和关闭大图。树场景不新增路径回放、公里数、编辑和上传功能。

## 实现隔离

- 新模块放在 `assets/travel-ring-tree/`，拥有独立模板、入口、树模型与数据适配；主页面只增加菜单按钮、独立弹层及初始化接线。
- 优先只读复用伞幕已经验证的 Three.js、相机操作、花园绘制和照片查看代码；树模型、布局与年份筛选在新模块内实现，不向伞幕添加主题开关，也不重构原伞幕。
- 同时满足本地文件入口与 HTTP 入口：沿用离线打包方式，不依赖运行时远程模块或默认照片请求。复用代码保留原有来源说明和许可证。
- 两个功能不共用活动场景状态。年轮树关闭时暂停并释放其独立页面资源；返回、隐藏标签页和减少动态效果设置沿用既有暂停原则。

## 降低复杂度与绘制预算

- 简化树干、枝条与叶簇，以少量几何体或实例绘制为主，不引入重型树木模拟、阴影后处理或额外框架。
- 照片使用现有缩略图绘制机制，点击查看原图时仍使用原记录。
- 花草参考现有花园的桌面/手机上限，不超过桌面 2400 株花、手机 800 株花；树冠不无限增加叶片。
- 空相册显示明确提示；图片加载失败沿用现有替代显示，仍可关闭。无法创建 WebGL 时显示提示并保留城市照片列表与原图查看入口，不留下不能退出的空白层。

## 验收与测试

- 菜单按钮、独立弹层、关闭和焦点恢复在 Edge 电脑/手机视口均正常，无水平溢出。
- 使用真实数据适配测试视频排除、重复到访、明确日期、首次到访及手动年份优先；未知年份不伪造。
- 浏览器测试覆盖年份强调与恢复、城市浏览、旋转缩放、原图查看、暂停和关闭释放；检查离线无外部图片或模块请求。
- 截图检查树枝可辨、照片没有变灰或严重重叠、地面年份和按钮不遮挡主体，花园仍保持紧凑。
- 验证伞幕目录内文件未被本次修改；运行现有伞幕测试与完整项目回归，逐项报告失败或跳过，不能以新场景通过代替原功能验证。
