# 匿名浏览器跨分享照片复用设计

状态：用户已确认方向；本文件待用户审阅。尚未修改产品代码、数据库或线上函数。

## 1. 目标与边界

同一匿名浏览器首次分享浙江，再分享浙江及其他省份时，已上传且内容完全相同的照片不重复上传、不重复计入照片容量，两个分享链接都保持可读。

- 保留免登录、单选／多选／全选、海报＋二维码、独立分享链接、原省份按钮更新原链接。
- 保留本地原资料、只读书本相册、多照片排版、摄影封面及 550ms 跟手翻页。
- 匿名身份沿用 `memoryShareBrowserIdentity`。去重只在同一身份内发生，不跨浏览器或用户共享。
- “相同”指压缩后的 JPEG 字节、SHA-256 和长度一致，不按文件名、城市名或视觉相似判断。编码结果不同视为不同文件。
- 压缩参数维持最长边 900px、JPEG 0.7、单文件不超过 307200 字节；照片和封面均参与去重，章节中的重复出现及顺序保留。
- 50,000,000 字节匿名浏览器上限与 800,000,000 字节全站上限不变。目录仍占数据库空间，访问仍消耗流量；两者不因照片复用而变为零。
- 不新增账号、历史分享管理、撤销、有效期、相似图片识别或全站跨用户去重功能。

## 2. 已核对的基线

基线提交 `ce5f599`。当前每份分享使用 `shareId/fileId.jpg` 独立路径，配额按每个会话清单的全部文件求和。`begin` 返回已上传文件，`finish` 发布目录；更新后旧会话整体删除。因此只有上传失败重试能复用自己的文件，不支持不同链接共用。

相关文件：`assets/memory-share.js`、`supabase/functions/memory-shelf-share/storage-handler.mjs`、`storage-validation.mjs`、`supabase/memory-shelf-storage.sql`。只读接口目前根据 v2 的单一 `storagePrefix` 签名，需增加共享文件目录解析。网页阅读器继续接收现有目录及城市照片响应，不重新设计 UI。

当前未提交的照片流、景点统计、`index.html` 无关片段、`1/` 与 `旅行资料/` 不属于此变更。

## 3. 方案选择

采用服务端“匿名身份＋内容哈希”的共享文件登记和分享引用。

前端缓存方案更少代码，但刷新、清除缓存和并发时不能证明文件仍存在或容量正确，不采用。全站按哈希共享会引入跨用户存在性探测和权限耦合，不采用。

新增共享文件表及引用关系，既有会话和容量表继续承担认证、发布和总额锁定。清理任务保存实际待删除的路径和计量，不另建通用任务系统。

## 4. 文件登记与引用

共享文件记录包含匿名 owner、SHA-256、字节数、服务端生成的 Storage 路径及状态。活动记录唯一约束为 `(owner_id, sha256)`；同一哈希但长度不一致拒绝，不返回其他身份的命中信息。

分享文件引用记录连接会话、逻辑 fileId 和共享文件；一次会话可以有多个逻辑位置引用一个物理文件。引用按会话建立，不按照片在页面出现次数计量。增加共享文件外键索引，用于检测其他会话引用。

待上传、已上传、删除中必须可区分。待上传文件只预留一次容量，已上传文件只计入一次已用容量。未删除成功的文件及遗留草稿仍占额度。删除中的文件不准建立新引用，避免签名链接指向即将删除的对象。

新目录存储为 v3，内部文件映射引用共享文件标识，不接受客户端 Storage 路径。读接口按映射解析，仅返回此分享实际引用的封面或所选城市照片签名地址；外部 reader 响应形状保持原样。v1/v2 读分支保留。

## 5. 发布流程与配额

1. 前端压缩并计算哈希，清单内部相同字节只保留一份文件，照片位置仍分别引用它。
2. 验证匿名凭证；先凭持有的旧管理密钥归属并处理可迁移旧分享。扫描原省份与顶部选择生成的管理记录，不能只扫描省份键。
3. `begin` 在数据库事务中解析已存在文件、建立本会话引用，只为缺失文件预留增量字节，返回已复用与待上传 fileId 及本次新增字节。
4. 前端只上传缺失文件。服务端重新检查 JPEG、实际长度与哈希，登记上传成功。客户端声称哈希命中不能代替认证或完整性检查。
5. `finish` 验证本会话全部引用文件已就绪，原子更新分享目录；相同 target 更新原二维码，新 target 生成独立二维码。
6. 移除被替换会话的引用；只有没有其他有效会话引用的文件才进入清理。Storage 实际删除成功后才释放计量。

前端不能再因“已用达到 50MB/800MB”直接拒绝，也不能用清单全部字节减剩余额度来判断：完全复用时允许新增目录；只有新增物理文件超额才拒绝。单次所引用独立文件的总字节仍不超过 50MB，省份／城市／照片数量限制保持原值。

界面沿用已有进度，说明“复用 N 个文件、本次新增 M MB”，避免让用户误以为再次上传了全部照片。不增加额外配置页。

## 6. 并发、取消与故障

- 所有配额与文件状态事务维持锁顺序：全站容量、匿名容量、文件记录（哈希排序）；Storage 网络操作放在事务之外。
- 两个会话同时引用新哈希，只创建一个文件记录和一次预留。仅一个上传操作取得该文件上传权；另一个提示等待并可重试，不重复写对象或提前发布。
- 对象写入后登记失败，保留预留；重试核对实际对象长度和哈希再恢复登记，不盲目接受“文件存在”。
- 相同会话重复 begin/upload/finish/cancel 均幂等；发布响应丢失后恢复同一目录，不新增引用或重扣额度。
- 取消仅移除该草稿引用。另一草稿或已发布分享仍在引用时，不删物理对象、不释放其容量。
- 无引用文件在事务内标记删除中并登记清理；并发 begin 不得引用删除中对象，待完成后重试。删除失败继续计量，并可再次清理。
- 不自动抢占进程崩溃遗留的上传锁，也不自动删除发布内容；维护必须核对 Storage 后修复，不能直接删除 Storage 元数据。

## 7. 旧分享逐步兼容

只有提供原管理密钥且归属同一匿名身份的分享才能纳入复用。公开二维码、shareId 或文件哈希不构成管理权限。清除浏览器凭证后不承诺仍能迁移旧分享。

### 旧 v2 Storage 分享

逐份核对旧会话中的已上传记录及真实对象。首次匹配的对象可以原地成为共享文件的规范路径，无需复制上传；其他旧目录逐步改为引用该规范文件，原二维码不变。

原目录指向旧对象期间不得删除它。切换目录与建立引用在同一事务完成，之后仅清理已无旧目录／旧会话引用的重复路径。被删除的重复副本实际消失后才减旧计量，不能仅按哈希重算容量而忽略仍存在的文件。

### 旧 v1 内嵌照片分享

核验凭证后，以原内嵌 JPEG 字节计算哈希，不重新编码已有副本。按文件逐步导入共享存储；全部文件就绪后，原子把原 shareId 目录切换到 v3，并释放旧 JSON 照片的计量。失败时旧目录和二维码保持可读，已落盘副本保留计量或按取消规则清理。

迁移不得暂时“减掉旧容量”来绕开上限；v1 导入若需额外临时空间而超过上限，明确提示迁移空间不足，保留旧链接，不能承诺立即节省容量。已有副本完全一致时优先引用已登记对象。此限制不影响成功迁移后的跨分享复用。

旧 v2 写客户端必须收到刷新升级提示，不能继续按旧会话整体清理目录而删掉已共用的规范对象。切换期间 v1/v2 只读接口继续工作；新写接口显式版本校验。

## 8. 权限与变更范围

共享登记、引用、清理表全部开启 RLS；撤销 PUBLIC/anon/authenticated 表访问及事务 RPC EXECUTE，仅 service_role 使用。RPC 保持 SECURITY INVOKER 并固定 search_path。客户端不获得 service_role、原始路径、管理密钥或其他身份命中信息。

私有 `memory-share-photos` bucket、JPEG 限制及短期签名机制保留。新路径由服务端生成；采用旧路径仅限核验过的旧对象，不信任客户端任意路径。查阅当前 Supabase changelog/官方文档并核对线上既有策略后再实施部署。

只修改分享上传、服务端计量／引用、旧版本解析、必要的进度文案和专项测试、交接文档。无关 UI、照片流、本地用户资料不变。实施计划需明确部署顺序、兼容窗口及回滚限制；共享引用启用后不得直接回滚到旧的整会话删除函数。

## 9. 验收标准

- 浙江 JPEG 合计 10MB，第二份“浙江＋江苏”新增 8MB；两份链接均可读，照片计量 18MB（不计目录开销），第二次只传江苏缺失文件。
- 相同照片用于封面、两个城市及多份分享，只占一份字节；位置、文字和排序完整保留。
- 同名不同照片分别上传；同图不同压缩字节不错误合并；其他匿名身份不能引用前一身份的登记对象。
- 达到配额但全部复用可发布目录；增加 1 字节超额拒绝，不产生未计量对象。
- 两个真实数据库连接并发创建相同文件，容量只预留一次；取消其中一个不影响另一个发布；多个不同新文件并发不得突破总额。
- 更新浙江链接、失败重试、丢失响应、取消、删除失败、上传登记失败，均不误删“浙江＋江苏”仍引用的照片，不重复扣减。
- 已持有凭证的 v1/v2 分享逐步转换后原二维码可读；迁移中断、空间不足、缺失对象和错误凭证均不破坏旧目录。
- 使用独立合成照片进行本地及独立数据库测试；上线前验证私有桶策略、RPC 权限、签名读取、实际容量及清理，并运行现有相册回归测试。未执行的并发或真机用例必须明确标记，不能用模拟测试声称已验证。
